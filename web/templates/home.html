Feature set

One gateway. Every control you need.

Enforcement happens inline on the request path — not after, from a dashboard. Everything below is live in the API today.

Atomic pre-flight check

Estimated cost is decremented from Redis quotas before the upstream call; true-up refunds the delta after. No double-spend, no race conditions.

Chapa microbilling

Sell AI credits to your Ethiopian customers in ETB. 3-way split — usage grant, platform fee, founder payout — computed automatically at checkout.

FIFO grant expiry

Usage grants are consumed oldest-first so expiry is handled correctly. Expired balances get swept cleanly by a periodic worker.

Dual quota scopes

Every call checks both the project-level bucket AND the per-end-user Redis balance. Either trip → 429 before the model sees a token.

Stream-safe metering

Streaming token counts are synthesized correctly across partial chunks — including Anthropic's split input/output stream events.

Fail-closed architecture

If the enforcement layer has a problem we block, not pass. API keys are SHA-256 hashed before storage — never in plaintext.

SpendGuard's Chapa integration auto-creates a subaccount for every project. Every checkout splits the transaction automatically — founder payout, SpendGuard platform fee, and the end user's AI credit grant.

Create a pricing plan

Set a charge amount, an AI credit allocation, and your split. SpendGuard hard-rejects plans where your credit grant exceeds what the processor actually leaves us.

3

Your user pays, gets credit

Chapa webhook → idempotency lock → usage grant row + Redis INCRBY. Credits are spendable instantly. You see every grant in the dashboard audit log.
